구독 토큰은 공식 앱 밖으로 나가지 못한다 — 구글이 먼저 선을 그었다

2026년 11월 15일 · 옵티웍 AI 데일리 · 고급

공유 · 구독
텔레그램에 공유 채널 구독 X에 공유
한 줄 요약 (GEO) Antigravity 구독 OAuth를 서드파티 하네스에 물린 계정이 다시 무더기로 막혔다. 같은 주에 구글은 /teamwork로 공식 표면 안의 멀티 에이전트를 자랑했고, 국내에선 수노로 부른 노래가 멜론 1위를 지켰다.

수집 범위: 국내 자동 수집 정상(11-15 07:46 KST, 후보 60, 오류 0). 추가로 ai_utilize 121쪽(620편, 11-14 19:4011-15 07:43)·chatgpt 14쪽(110편) 목록을 받아 조회·댓글 상위 38편 본문·댓글을 직접 읽음. 해외: 레딧 RSS 2/8(LocalLLaMA·ClaudeAI; 나머지 빈 응답), HN 1면 30, 1차 자료(Antigravity 약관·Google AI Developers Forum 답변, GitHub 이슈, Google Research 블로그, 국토교통부·산업통상부 참고자료, Crissy Field 보고서, U-M 발표), 보도(연합뉴스·한겨레·뉴시스·AI타임스), AA 페이지 데이터. 11-1211-14에 다룬 Claude 장애·Duet 리셋·Nvidia 건은 새 사실이 없어 제외.

오늘 핵심 세 가지

  1. Antigravity 구독 의 서드파티 사용 = 약관 위반, 정지 재개(약관·포럼 확인 / 11-14 웨이브 규모 미확인). 약관 6조가 “제3자 소프트웨어로 서비스 접근(예: OpenClaw + Antigravity OAuth)”을 명시적 위반·정지 사유로 규정하고, 포럼 답변은 oauth-personal을 공식 표면(앱·CLI·IDE·공식 확장)으로 한정, agy -p 래핑도 금지. 국내에선 11-14 저녁부터 OpenCodex·Hermes·OMP 같은 사용자 정지 보고가 이어졌고, 해외 GitHub엔 11-05~06(미국) 선행 웨이브 기록이 있음.
  2. 수노 보컬 곡이 멜론 톱100 1위(확인). 머무르 「꿈꾸던 어른이 되었나요?」 11-13 17시 1위 → 11-15 07시 유지(뉴시스). 24h+1h 합산 차트라 단기 스트리밍으로 버티기 어려운 구조인데도 갤러리에선 “바이럴·사재기” 주장이 나왔고 대다수가 반박. 저작권료는 음저협 미신탁으로 0원.
  3. GPT-6.2는 여전히 카탈로그·체인지로그·AA 어디에도 없음(확인), “6.2 Sol 라우팅” 체감·Krypton 아레나설은 미확인. 동시에 ChatGPT 갤러리는 ‘자살 언급 누적 → 영구 정지’ 추측과 반박으로 하루를 보냄(사례 미확인).

국내 커뮤니티

1) 「❗지금 절대 구글 OAuth 서드파티에 물리지 말것❗」 — 반중력 밴웨이브 (약관 확인 / 규모·기준 미확인)

확인(1차 자료):

  • Antigravity 추가 약관 6조: “using third party software, tools, or services to access the Service (e.g. using OpenClaw with Antigravity OAuth) is a breach” → Antigravity 및/또는 Gemini CLI 계정 정지·해지 사유.
  • Google AI Developers Forum 공식 답변: 개인 로그인("auth": {"type": "oauth-personal"})은 Antigravity App·CLI·IDE·공식 IDE 확장(VS Code, Visual Studio, IntelliJ 계열, Zed, Xcode, Eclipse)에서만 지원. 플랜에 포함된 Gemini·Claude 추론 모델 접근도 이 표면 한정. agy -p(헤드리스)를 서드파티 앱 안에 감싸는 것도 위반. 서드파티 하네스엔 AI Studio API 키(GEMINI_API_KEY) 또는 Gemini Enterprise/Vertex AI를 쓰라고 권고.
  • 예외적으로 Google의 수정되지 않은 antigravity-acp 바이너리 + 네이티브 브라우저 OAuth를 호환 ACP 에디터에서 단일 사용자 대화형 코딩에 쓰는 건 지원된다고 함. 반면 로컬 agy 로그인 파일을 읽거나, 자격 증명 파일을 평문으로 쓰거나, agy로 쿼터를 폴링하거나, 멀티 워커 풀을 돌리는 플러그인은 금지 사례로 명시.
  • 정지 증상·절차: 403 PERMISSION_DENIED / reason: TOS_VIOLATION / domain: cloudcode-pa.googleapis.com, “This service has been disabled in this account…”. 이의 신청은 계정당 1회, 자동 검토 48~72시간·확인 메일 없음, 복구 후 재위반 시 영구 정지. 재로그인 전 myaccount.google.com/permissions에서 OAuth 그랜트 철회 필수(로컬 파일 삭제만으론 그랜트가 남음).
  • 선행 웨이브(GitHub 이슈): CLIProxyAPI #7296은 11-06 03:00(UTC+8) 무렵 3개 중 2개 자격 증명이 4분 간격으로 동시 사망, 정지 범위는 Cloud Code 서비스 한정(구글 계정·구독·토큰 갱신·모델 카탈로그 조회는 정상)이라고 보고. OmniRoute #19266은 11-05~06 4개 계정 ToS 정지 + 1개 계정 인증 요구를 기록했고, 이후 프로젝트 문서에 “스텔스·핑거프린트 옵션은 계정당 트래픽을 줄일 뿐 사용을 허가된 것으로 만들지 않는다”는 경고가 추가됨.

국내 반응(경험담 — 미확인):

  • 경고글(댓글 26): “11-14자로 본격 시작, 인쫀쿠·터쫀쿠(해외 우회 결제 구독)든 정가든 핑거프린트에 서드파티 하네스·루프에서 구독 OAuth로 Gemini 호출이 잡히면 권한 회수, 한 번은 어필로 복구되지만 재사용 시 영정.” 댓글엔 “ACP·CLI 경로는 문서상 된다·안 된다가 섞여 있어 위험은 같다”는 정리.
  • 「ouath 잘못 연결한 건지 agy 정지먹었는데」(23): OpenCodex 라우터 경유 → 정지. “앙망문(이의 신청) 쓰면 풀어 주고 그 뒤 안 까불면 됨”, “agy만 막히고 구글 전체는 못 봤다”(GitHub 보고와 일치).
  • 「인쫀쿠 말고 AGY OAUTH 정지된 사람도있음?」(16): “11만 원 정식 울트라, 워커로 쓴 적도 없는데 정지” vs “계정 승계형 우회 구독을 제일 싫어하는 패턴이라 잡은 것, 정식 구독 정지 사례는 최근 못 봤다”. 「구글 밴 특징 가르쳐준다」는 “울트라 장기 구독으로 hermes·omp·opencode·cliproxyapi 다 물려도 멀쩡”이라는 반대 사례.
  • 「와 반중력이거 -p도 정지구나」: “얼마 전 안내가 뒤집혔다”, “자동화(서드파티 에이전트 호출)가 문제”, “Claude reviewer로 Gemini 쓰던 것도 위험한가” 질문.
  • 패밀리 플랜 멤버가 “메일 없이 무료 티어로 떨어졌다”는 댓글엔 “그건 정지가 아니라 관리자가 플랜을 해지한 것”이라는 답.

해석: Anthropic이 Claude 구독 OAuth의 제3자 사용 범위를 둘러싸고 겪은 논쟁(11-10 고급판에서 다룬 passthrough 구성 등)을 Google이 더 강하게, 더 먼저 문서화한 형태입니다. 하네스 선택권이 필요한 워크로드는 API 키 과금으로 옮기는 비용을 계산해야 하고, EEA·스위스·영국 사용자 대상 서비스라면 Gemini API 추가 약관상 유료 서비스만 허용된다는 점(OmniRoute 문서 인용)도 체크 대상입니다. “정식 구독은 안전”이라는 갤러리 통념은 근거가 약합니다 — 공식 문서는 결제 경로가 아니라 접근 표면으로 선을 긋습니다.

  • 확인 가능한 것: OpenAI는 이번 주 정지 기준 변경을 발표하지 않았습니다. 데이터 내보내기는 정지 후 불가할 수 있다는 사례가 반복됩니다(사례 기반).

해외

1) Lovable 159,041개 프로젝트 감사 (확인 — Crissy Field, HN 1위 533점)

  • Common Crawl에서 2025-12~2026-09 Lovable 프로젝트 159,041개 식별 → 34,545개가 Supabase 사용 → 24,664개가 첫 로드에 DB 레코드를 전송 → 같은 anon 키로 추가 읽기 전용 요청 시 7,403곳(30%)·10,560개 테이블에서 이메일 포함 레코드 접근.
  • 사례: 독일 포럼 프로필 8만+·채팅 20만+, 여권 번호 1,000+, 티켓·결제 수만 건, 이메일 28만 통, AI 요약된 내부 메일.
  • 저자 단서: 30%는 확정 유출률이 아님(공개 연락처·테스트 데이터 포함 가능, 이메일 없는 개인정보는 누락). 핵심 원인은 설정 누락 같은 반복 패턴이고, “패턴이 같아 한 번 통한 공격이 다른 앱에도 통한다”는 점이 AI 빌더 고유 위험이라고 지적.

2) 비영어 추론의 에너지 격차 (연구 확인 — U-M, EMNLP 2026)

  • Qwen 3·Gemma 3·Llama 3.1, Belebele(122개 언어 독해) + 번역한 수학·개방형 프롬프트. 비영어는 1.4~180배 에너지, 서유럽어는 대체로 2배 이하, 힌디 7.9배·벵골 15.3배. 모델 크기·하드웨어를 바꿔도 격차 유지.

  • 한국어 수치는 보도자료에 별도 표기 없음. 실무 함의: 토큰 과금 API에서 긴 시스템 프롬프트·도구 설명은 영어로, 출력만 한국어로가 비용·컨텍스트 양쪽에 유리할 수 있음(언어별 토크나이저 효율은 모델마다 다르니 직접 측정 권장).

3) Google Research — Antigravity /teamwork (벤더 발표)

  • 설계 원리 두 가지: ① 병렬 탐색 + 전용 반증기(falsifier)(Lean 4 증명 검사, 수정하지 않은 테스트 스위트, 시뮬레이터, 하드웨어 카운터)로 후보 자동 검증, ② 컨텍스트 분할 — 각 에이전트에 필요한 파일·도구만, 코디네이터가 새 후임에게 인계, 비평·감사 에이전트는 생산자의 추론 없이 깨끗한 컨텍스트에서 검증.
  • 결과(구글 주장): Courtade–Kumar 추측(2013) 일반형 증명·Lean 5천만 줄, Weil 추측 Lean 형식화 약 180만 줄(서브에이전트 28,800회), Zircon 마이크로커널 잔여 C++ → safe Rust 약 80만 줄(arm64 부팅), libgav1 Rust 포팅이 원본 대비 20~30% 빠름, 9x9 바둑 엔진 8일 +2,600 Elo, Borg 스케줄링으로 일부 TPU 선점 24%↓. /boost는 강결합 코드엔 병렬 분할보다 순차 구현·수정이 낫다는 궤적 분석을 반영.
  • 외부 공개: /teamwork·/boost·Deep Review 사용 가능, 학계 1만 명 최고 등급 6개월 무료 신청. 같은 주에 서드파티 OAuth를 막고 공식 표면의 하네스를 키우는 것 — 전략적으로 일관된 그림입니다.
