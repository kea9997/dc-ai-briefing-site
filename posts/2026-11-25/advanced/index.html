해외 커뮤니티·1차 자료

1) VP ≠ VNP — OpenAI 동일 결론 발표, Anthropic CI 독립 재현 (공개 확인 / 정당성 미확인)

  • OpenAI openai/math(“November 23 edition”, 30쪽): Theorem 1.1 — 명시적 VNP 족에 대해 산술 회로 크기 하한 exp(Ω((log n)^{5/4})), 모든 체. Corollary 1.2로 directed Hamiltonian cycle 다항식(모든 체)·permanent(표수 2 제외)로 이전. 족은 “self-delimiting prefix가 인코딩한 프로그램의 accepting path 수”를 계수로 하는 대각화형 구성 — 증명 축은 “유클리드 공간에서 가격 매긴 tensor network의 rigidity”와 “wire budget 안에서 degenerating 비균일 회로 계산을 replay하는 대각화”. Lean 분리 정리 OAI/Computability/VPVNP/ClassSeparation.lean.
  • 선후(확인 — HN 커밋 비교): Anthropic 커밋 11-23 12:04 PST, OpenAI 17:30 PST → 공개 기준 Anthropic 5.5시간 선행. OpenAI history.md의 “11-06 획득”은 자기 기록. HN 제목 “before Anthropic”은 제출자 표현.
  • 하한 형태 비교 보류: Anthropic은 m^{c(log m)^{1/3}} = exp(c(log m)^{4/3}) 꼴, OpenAI는 exp(Ω((log n)^{5/4})) — 지수만 보면 전자가 강해 보이지만 m·n 정의(변수 수·차수 매개)가 달라 직접 비교는 원문 대조 전까지 보류.

의미 — 그리고 바꾸지 말 것

  • 기본값이 정책이다. T3의 opt-out 기본값, Fable의 소유권 미지정 시 ‘덧붙이기’ 기본 동작, Claude Approvals의 정책 파일, 하네스별 추론 문체 — 오늘 이슈는 모두 명시하지 않았을 때 무엇이 일어나는가였다. 모델 교체보다 기본값 감사가 ROI가 크다.
  • 하네스는 비용 레버. 같은 모델에서 점수 차는 수 점이지만 작업당 비용은 수 배. 코딩 가성비 판단은 “모델 × 하네스” 쌍으로 해야 하고, 공개 모델을 벤더 하네스에 끼울 땐 스타일 부적합(Codex×GLM) 가능성을 먼저 의심할 것.
  • 검증 사슬의 독립성. VP ≠ VNP 재현은 통과했지만 수행 주체가 Claude였다. 기계 검사는 독립 커널(nanoda)로 다변화됐어도 ‘진술 충실성’ 판단은 여전히 사람 전문가 몫.
  • 바꾸지 말 것: 주가·Form 4는 스택 결정 요인이 아니다. AA 상위권 불변 → 모델판 유지. Codex·Claude Code 파이프라인의 모델 ID 고정 유지(Chat·Work 통합은 UI 시범). T3 Code는 삭제보다 T3CODE_TELEMETRY_ENABLED=false(부팅 전 env 또는 managed policy)로 차단 후 업데이트 확인.

시도 후보

  1. Ownership A/B: 같은 리포·같은 과제 5개를 ownership 문장 유무로 돌려 git diff --stat·출력 토큰·테스트 통과율·의도치 않은 동작 변경 수를 기록. 공개 API가 있는 모듈은 “호환성 진입점 유지” 문장을 반대로 명시.
  2. 에이전트 GUI egress 감사: T3·기타 GUI를 샌드박스에서 띄우고 ss -tp/DNS 로그로 ingest.t3.codes·*.posthog.com 등 송신 도메인 확인 → 사내 배포 시 env·policy로 차단, 커스텀 엔드포인트 이름에 사내 정보 넣지 않기.
  3. Eval 트래픽 분리: 회귀 벤치는 전용 API 키·워크스페이스·메타데이터 태그로 분리하고, 실행 스크립트·스케줄·결과 저장 위치를 커밋으로 남겨 증류 의심 시 즉시 소명 가능하게.
  4. 하네스 스윕(로컬판): 자주 쓰는 공개 모델 하나로 Claude Code·OpenCode·mini-swe-agent·Codex에 같은 과제 10개 — 점수보다 과제당 토큰·턴 수를 먼저 비교. AA 결과처럼 순위가 뒤집히는지 확인.
