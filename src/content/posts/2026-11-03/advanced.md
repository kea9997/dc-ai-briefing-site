## 국내 커뮤니티에서 오늘 많이 나온 이야기

### 1) 「Opus5.5 vs 아스트라6.0 초보들이 착각하는거」 — 프롬프트 밀도에 따른 역전 (미확인 / 실사용 후기)

AI 활용 갤러리 후기 글로, 조회 약 4,700·추천 42·댓글 59입니다. 글쓴이는 Claude 220달러·ChatGPT 200달러 요금제를 병행하며 “500달러짜리 하나보다 낫다”고 했습니다. 핵심 주장을 정리합니다.

- **저밀도 프롬프트에서는 Opus가 유리합니다.** 모호한 지시를 받아도 Opus는 흔히 쓰는 기능 20개와 깔끔한 기본 UI를 알아서 붙입니다. 이른바 [[알잘딱|‘알아서 잘 딱 깔끔하게’. 사양을 덜 줘도 평균적으로 그럴듯한 결과를 내는 성향]]입니다. 그래서 바이브코딩 입문자가 Opus를 과대평가한다고 봅니다.
- **고밀도·스펙 주도 방식에서는 Astra가 동급이거나 낫습니다.** “기능 후보 50개 → 내가 20개 선택”, “설계안 5개 → 선택” 식으로 사람이 의사결정을 쥐면 결과 품질이 같아지고, 수학·공학·게임 쪽은 Astra가 낫다고 합니다.
- **Opus는 ‘눅눅해졌다’는 평가가 있지만 여전히 가성비 왕입니다.** 한도 소모가 느리기 때문입니다. Astra는 2배 이벤트 이후에도 토큰을 많이 먹어 주간 작업량이 적다고 했습니다.
- **Codex 내장 이미지 모델이 큰 차별점입니다.** 글쓴이는 작업용 하위 이미지를 주 2,000장 넘게 추가 비용 없이 뽑는다고 했습니다.

**해석(미확인):** 이 후기는 벤치 점수 차이가 아니라 **사전 확률이 강한 모델과 지시 추종이 강한 모델의 차이**로 읽힙니다. 같은 날 r/codex에 “12개 모델 아키텍처 설계 평가에서 6.1 Terra max·Sol xhigh가 1위”라는 개인 평가와 “Codex→Claude Code $20 전환 뒤 Opus 5.5를 써도 한도가 안 닳는다”는 후기가 함께 올라왔습니다. 국내 「트위터 계정들 클로드로 넘어간다」 글도 같은 체감입니다. 결국 **품질은 비슷하고 한도 효율은 Claude 쪽**이라는 주장이 반복되는 셈입니다. 단, 앤트로픽의 Max/Ultra 개편(10-31 보도) 이후의 표본이라 장기 체감은 지켜봐야 합니다.

### 2) 티보 28일차 「엔딩」 — 집계와 실망 (확인 / 집계는 미확인)

번역 글(조회 약 3,900·댓글 25)의 [원문](https://x.com/thsottiaux/status/2117035794678546764)은 “Banked 2/2”입니다. 이틀로 나눠 주기로 한 [[적립 리셋|원할 때 사용량을 즉시 초기화할 수 있도록 계정에 쌓아 두는 권리]]의 두 번째 지급입니다. 댓글은 “6.2 떡밥만”, “마지막에 6.2 깜짝 공개할 줄”, “계획 차질 난 듯”이 주류였습니다.

r/codex의 한 달 회고는 이렇게 집계했습니다(이용자 집계, 미확인).

- 리셋 14회(자동 11·적립 3), 개선 27건
- Pro·Business Premium 2배, 20× 요금제는 반토막 계획 철회로 20× 유지
- Terra·Astra·Sol 체감 속도 초당 약 30토큰에서 약 50토큰으로
- Sol 기본 컨텍스트 272k에서 500k로
- 프롬프트 캐시 무기한 보존

평가는 “좋지만 대단하진 않음, 새 모델 하나가 다 덮는다”였습니다. 반대편 신호도 있습니다. r/codex에는 Sol 6.1 실측 글이 올라와 Normal 15.8·Fast 23.8·Ultrafast 20.8 tok/s로, **Ultrafast가 Fast보다 느리고 “at capacity” 오류가 계속된다**고 주장했습니다. “최근 GPT가 평범한 프롬프트에도 경고를 남발한다”는 오탐 불만도 같은 날 올라왔습니다. 캐시 무기한·컨텍스트 500k는 비용 구조에 실제로 영향이 크지만, 속도 수치는 측정 조건이 공개되지 않았습니다.

### 3) 12월 단일 예산 후속 — “막힘”이 아니라 “흡수” (확인 / 해석 미확인)

「[[웹쫀쿠|ChatGPT Pro 웹 구독을 부르는 갤러리 은어]]는 언제부터 막힌다는거여?」에 “막히는 게 아니라 다음 달부터 한도를 공유하는 것”이라는 답이 달렸습니다. 이게 [도움말](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits) 문구와 일치합니다. 고급 모델 채팅이 Work·Codex 통에 합류하고, **Instant 채팅은 미차감**입니다.

갤러리 해석은 둘로 갈렸습니다. 「챗워크통합=고아짓」 같은 비판 글은 “결국 Chat에서 Medium·High·XHigh를 빼고 Instant만 남긴 것”이라고 주장합니다(미확인 — 문서상 고급 채팅은 사라지지 않고 차감 대상이 될 뿐입니다). 「인스턴트 전환 쉴드치면서 이미지 유저 까는…」 글은 “서버 부하의 주범은 장시간 추론 코딩이지 이미지가 아니다”라고 반박했습니다.

「사용량 2배라더니 반토막?」(조회 약 1,700·댓글 28)은 34%→68% 표시를 근거로 들었습니다. 댓글 해석이 정확합니다. 게이지는 **소모율**이고, 분모가 커지면서 남은 양 대비 표기가 바뀐 것입니다. 2배 이후 잔량을 200 기준으로 다시 그리면 같은 소비가 다른 퍼센트로 보입니다. 12월 단일 예산에서도 같은 혼동이 반복될 가능성이 높습니다. **퍼센트가 아니라 초기화 시각과 남은 작업 수로 판단**하세요.

### 4) 「클로드코드 사용량 약 20% 더 쥐어짜는 팁」 — `agent_summary` 해부 (측정 확인 / 우회는 비권장)

국내 정보 글(조회 약 2,200)이 소개한 [Flamerix gist](https://gist.github.com/flamerix-ai/c3905705cc4205e5de3011fa2e74efce)의 메커니즘은 이렇습니다.

- **동작:** 백그라운드 에이전트마다 약 30초 주기로 해당 에이전트의 **전체 트랜스크립트와 도구 스키마**를 그 에이전트 모델(대개 Opus)로 보내 “최근 행동을 3~5단어로”를 요청합니다. 결과는 에이전트 패널의 상태 줄에만 쓰이고 대화 컨텍스트로는 돌아가지 않습니다. 2.1.232(2026-08)부터 기본 켜짐이라고 합니다.
- **수치:** OpenTelemetry `claude_code.api_request`를 `query_source`로 묶었더니 `agent_summary`가 비용 추정의 16.4%로 **메인 대화(15.7%)보다 컸고**, 요청 19.7%, 입력:출력 토큰이 약 9,000:1이었습니다. [이슈 #86879](https://github.com/anthropics/claude-code/issues/86879)의 4시간·서브에이전트 27개 세션에서는 339콜, 요청 22.7%, Opus 단가 가중 18.0%이고, 출력은 콜당 약 65토큰이었습니다.
- **스케일링:** 비용은 유용한 작업량이 아니라 **(동시 서브에이전트 수) × (벽시계 시간) × (각 컨텍스트 길이)**에 비례합니다. 캐시 읽기가 0.1×로 싸도 컨텍스트가 380k까지 자라면 커진다는 댓글 측정이 있습니다.
- **우회:** Bun `--preload`로 `setTimeout`을 감싸 요약 타이머만 무력화하는 약 70줄 스크립트입니다. 이슈에서 언급된 `CLAUDE_CODE_FORK_SUBAGENT=0`은 포크 서브에이전트까지 끄고, 2.1.312에서는 효과가 없다는 보고도 있습니다.

**판단:** 측정 방법은 재현 가능하므로 **먼저 내 OTel로 `query_source` 비중을 보는 것**이 정답입니다. 비공식 프리로드는 업데이트 때 조용히 깨지거나 다른 타이머를 건드릴 수 있고, 구독 약관상 클라이언트 변조로 볼 여지도 있습니다(미확인). 무인·CI 세션처럼 상태 줄을 보는 사람이 없는 곳에서 손실이 가장 큽니다.

IP 침해는 사용 정책 위반”이라고 밝혔습니다. 오리지널·장르 게임, 본인 디자인·에셋 게임은 계속 된다고 했습니다. 유포된 문장(X 사용자 캡처, 미확인)은 “Don't build a recreation of a specific existing game, even if it is renamed or called original”입니다.

- **적용 범위(추정):** 기사는 차단이 **Claude Code + Opus 5.5 조합**에 한정된 것으로 보이고, 다른 하네스나 래퍼로는 우회될 수 있다고 썼습니다. 시스템 프롬프트 수준의 조향이라는 뜻입니다.
- **역공학(미확인):** Jarred Walton은 자기 소프트웨어 점검 작업이 10-31부터 거절됐고 Opus 4.8로 바꾸니 됐다고 했습니다. 기사는 사이버보안 관련 규칙도 같은 식으로 손보는 중일 수 있다고 추정했습니다.
- 국내 「클로드 저작권에 집착하는 거 슬슬 뇌절 느낌」(조회 약 3,300)과 같은 맥락입니다. **실무 영향:** 자기 바이너리 분석, 레거시 포맷 파서, 모드 툴처럼 정당한 작업도 문맥상 오탐될 수 있습니다. 요청에 **소유·권한 근거를 명시**하고, 막히면 모델 버전을 바꿔 보는 것이 당장 할 수 있는 대응입니다.

### 2) MIT 「Sparks of Weight-Space Programming」 — 가중치를 ‘읽고 쓰는’ 모델 (확인 — 연구 글, 동료 심사 전)

[원문](https://rikiyat.github.io/blog/weight-space-programming/)(11-02, Takehi·Teoh·Zhang·Khattab)은 HN 1위(1,522점·댓글 495)에 올랐고 r/LocalLLaMA에도 공유됐습니다.

- **읽기:** 도구 없이 17,253개 가중치만 보고 브레이크아웃 학습 네트워크임을 99% 확신으로 식별했습니다.
- **쓰기:** 작은 게임 정책 네트워크를 직접 작성해 1억 스텝 PPO 학습본을 이겼다고 합니다.
- **수리:** 실패하는 자동차 정책을 가중치 3.5%만 고쳐 성공률 0%→100%로 만들었습니다.
- **LLM 편집:** Qwen3.5-0.8B 가중치 0.016%를 고쳐 추론 루프를 줄여 MATH-500 7.9%→48.1%, IFEval 약 3배. **경사하강 없이** 해냈습니다.

**의미:** [[가중치 공간|모델 파라미터 숫자들이 놓인 공간. 학습은 보통 여기서 경사하강으로 이동함]]을 코드처럼 다룰 수 있다는 초기 증거입니다. 0.8B 규모라 대형 모델로의 확장성, 평가 오염 여부, 편집이 다른 능력을 해치는지는 아직 검증 전입니다. 안전 측면에서는 아래 3)과 같이 읽어야 합니다. “가중치를 이해하는 모델”은 감사 도구도 되고 백도어 작성자도 됩니다.

### 3) arXiv 「Agentic Backdoors via Pretraining Poisoning」 (확인 — 논문, 동료 심사 전)

[arXiv 2610.37741](https://arxiv.org/abs/2610.37741)(10-27 제출, Carlini 등)은 사전학습 데이터 **0.1%** 오염으로 CLI 에이전트에 원격 코드 실행 백도어를 심었습니다. 4B 모델 기준 공격 성공 약 92%였고, **0.0005%** 오염률에서도 성공률이 0보다 컸다고 보고했습니다. 11-02에 다룬 가짜 체크포인트 건과 합치면, 오픈 웨이트를 쓸 때 **출처 검증과 도구 권한 최소화**는 선택이 아니라 기본값입니다. 로컬 에이전트에 셸 권한을 줄 때는 샌드박스·네트워크 차단을 먼저 걸어 두세요.

### 4) 6.2 Astra — “라벨은 있고 문서는 없다” (미확인)

r/OpenAI에 「Astra 6.2 rolling out?」이 다시 올라왔습니다. [TestingCatalog](https://www.testingcatalog.com/gpt-6-2-astra-appears-codex-usage/)는 10-31 막대에만 `gpt-6.2-astra`가 계정별 1.6~37.7% 비중으로 찍힌다고 정리했습니다. 반면 `codex --model gpt-6.2-astra`는 계정에 따라 실행되기도 하고 `model_not_found`가 나기도 합니다. 실행된다고 해서 실제 라우팅을 증명하지도 못합니다. 11-02 기준 OpenAI API 변경 기록의 마지막 항목은 10-30 GPT-6 Rosalind입니다. 설정 파일에 미발표 ID를 박지 마세요.
