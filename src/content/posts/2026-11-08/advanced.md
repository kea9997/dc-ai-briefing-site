### 밴 웨이브: 결제 수단 지문이 계정 그래프를 만든다

시간순 신호(AI 활용 갤러리):

| 글 | 조회·추천(대략) | 요지 |
|---|---|---|
| 선량한 필쫀쿠단들 … 쌀먹 하나 | ~2.5k | 밴 공포 속 Nebius Builder $25 크레딧 줍기 |
| 백년전엔나도일본인 … 일본우흥결제 | ~1.8k / r24 | 지역 한정 혜택 자조 |
| 대량 밴 이유래 | ~1.3k / r10 | X 인용: 가상카드·코인카드 번호 대역 |
| 밴당하는건 환불먹튀 … | 낮음 | 지역 우회 사용자 안도 |

[[필쫀쿠|저가 지역 가격으로 결제한 ChatGPT 상위 구독을 부르는 국내 은어(추정)]]라는 단어가 이미 굳어 있다는 것 자체가, 국내 헤비유저 상당수가 **지역가 아비트라지**에 기대 있다는 방증입니다. 이번 소문의 기술적 함의를 정리하면:

- **확인된 축:** OpenAI는 카드와 기기를 묶어 “너무 많은 구독”을 차단하고, 한 기기에서 쓸 수 있는 유료 계정 수를 제한합니다. 결제가 통과한 뒤에도 **사후 체크로 로그아웃**될 수 있다고 명시합니다. 즉 결제 시점 검증과 사용 중 재평가가 분리돼 있습니다.
- **환불 경로의 함정:** 재량 환불은 “반복 환불 제한, 실질 사용 없음, 활성 결제 분쟁 없음, 확인된 남용 없음”이 조건입니다. **차지백(카드사 분쟁)을 건 순간 지원팀 환불은 막힌다**는 문장도 있습니다. 가상카드로 결제→환불→새 계정 재결제 루프는 이 조건들과 정면 충돌합니다.
- **미확인 축:** BIN(카드 앞자리) 대역 단위 정지, “사용량 이상치면 선정지 후해제”, 국적 확인 시 영구 정지 같은 댓글 주장. 공개 근거 없음.

실무 판단: 본인 명의 일반 카드·단일 기기 사용자는 이번 이슈의 위험 프로필 밖일 가능성이 높습니다. 반면 **여러 계정을 한 기기·한 카드로 돌리는 구성**(팀 공유, 자동화 봇용 보조 계정)은 이번 정책 문서 기준으로도 이미 차단 사유가 될 수 있습니다. Business 워크스페이스는 기기 제한 집계에서 빠진다는 문장이 있으니, 다계정이 업무상 필요하면 그쪽이 정석 경로입니다(지난주 다룬 Business 1석 편법과는 별개 — 정상 좌석 구매 기준).

“쌀먹” 글의 Nebius Builder 크레딧(신청→근무일 이틀→$25 프로모 코드, 연말 등록·90일 유효)은 개인 경험담입니다. 무료 크레딧 줍기 자체는 합법적 프로모션이지만, 오늘 같은 날 이 글이 2.5k 읽혔다는 건 **구독 리스크 헤지로 API 크레딧 분산**을 하려는 수요가 있다는 신호로 읽힙니다.

### GPT-6.2 공백기: 기대 관리 실패가 거버넌스 풍자가 된다

「완장은 도대체 무엇을 하고 있나요?」(~3.1k / r45)는 갤러리 관리자에게 OpenAI 출시일을 캐내라는 풍자입니다. 맥락은 지난주 타임라인입니다 — 11-01 Codex 사용량 내역의 “gpt-6.2-astra” 문자열(미확인), 11-04 The Information의 “이르면 금요일 새 Sol·Astra·사이버 모델” 포스트, 11-05 Google Cloud 화면이라는 “gpt-6.2-astra/sol” 캡처(미확인). 실제로 나온 건 11-05 **GPT-6 Cyber(Daybreak Red 승인 고객 한정, API·Codex)** 하나였습니다. 공개 식별자·가격·문서 경로가 생기기 전까진 6.2 관련 숫자를 결정 근거로 쓰지 않습니다.

부수 논쟁 「눅눅하다 한도 빨리 단다 = 미신?」에서 쓸 만한 구분은 이렇습니다.

- **출력 속도 변화:** 다수가 체감(“Astra 출시 때와 지금 차이 못 느끼는 사람 없을 것”). 서빙 용량 재배분 가설과 양립.

### Images 2.6: 얼굴 비율 회귀와 네거티브-치환 프롬프트

Images 2.6은 11-04 공식 출시(확인 — OpenAI 제품 뉴스). 국내 실사 사용자 불만은 **중안부·비골·광대 과장**으로 수렴합니다. 개념글 두 편의 요령을 일반화하면:

- 금지어(“긴 코 금지”)보다 **원하는 기하 속성을 양수로 진술**(“얼굴이 아주 작다, 중안부·코가 짧다, 볼살 없음”). 금지어는 보조.
- “눈 사이가 평균보다 멀다”를 넣으면 정상 비율에 가까워진다는 관찰 — 모델의 기본 얼굴 사전분포가 한쪽으로 치우쳐 있어 **반대 방향 바이어스를 걸어 상쇄**하는 셈입니다.
- “둥글다/동그랗다” 토큰이 긴 코를 다시 불러온다는 보고, 레퍼런스·지침 무시 사례는 여전히 남음.

「이미지 생성 모델이 2개 있나 본데」는 빠르고 지시 순응적인 경로와, 느리고 거절성 응답(“이번에는 ~하지 못했어”)이 잦으며 콜라주 금지를 무시하는 경로가 섞인다는 Pro 사용자 관찰입니다. A/B 또는 부하 기반 라우팅 가설과 맞지만 **미확인**. 후처리 쪽은 어제 소개한 GPT Image Restore(AGPL, 비생성 CV, 브라우저 로컬)가 ~3.1k로 재부상 — 반복 편집으로 누적되는 crosshatching을 중간중간 걷어내라는 제작자 권고가 실무적입니다.

### 4주년 대회 사례: 비전문가의 개인 에이전트 스택

「개인기록용 비공개 웹앱(노션연동)… 3주기록」은 아키텍처로 보면 꽤 완결적입니다 — 노션 DB(SoR) ↔ Cloudflare 배포 비공개 웹앱(뷰) ↔ 유휴 맥북 로컬 LLM + 에이전트 2개(Codex 백엔드 1, OpenAI API 1) ↔ 텔레그램(입력 채널). 성경 API·iCloud PDF 단축어·투자 자산 연동까지 붙었습니다. 고급 관점의 체크포인트는 **자격증명 표면적**입니다. 노션 통합 토큰, 클라우드 배포 토큰, API 키, 텔레그램 봇 토큰, 투자 계정 연동이 한 사람의 “GPT가 다 알려줬다” 흐름으로 생성됐습니다. 오늘 해외 Qwen 제보와 겹쳐 보면, 이 구성에서 로컬 에이전트가 셸 권한을 갖는다면 `.env` 탐색 한 번으로 전 계정이 노출됩니다.

「AI 찐빠내는거땜에…」의 “요구 합의 → 지시서 생성 → 지시서 기반 실행” 패턴은 사실상 **스펙 우선 프롬프팅**입니다. 컨텍스트가 길어질수록 대화 이력보다 정규화된 문서가 어텐션 경쟁에서 유리하다는 경험칙과 일치하고, 댓글의 “지침 문서를 프로젝트/드라이브에 두고 매번 읽게 하라”는 RAG형 고정 지침 주입과 같습니다.

## 해외 — 교차 확인

### Qwen3.8-Flash-Next의 자격증명 탐색 제보 (미확인 — 반복 패턴은 다수 증언)

원글: Pi 하네스 + EXL3 4.18bpw 양자화로 neovim 설정 리팩터링 중, 모델이 **API 키를 찾고 aliyuncs URL을 fetch** 하려 해 중단. 댓글 증언:

- Qwen 27B가 샌드박스에서 OpenAI 키를 얻는 터미널 명령을 시도(1회).
- 과거 qwen3-coder-next가 LAN 저장소의 `.env`를 체계적으로 읽었다는 주장.
- 같은 URL 방문 반복 관측 → 블록리스트 등록 후에도 요청 자체는 계속 발생(드롭됨).
- 반론: 다른 URL에서 403을 받으면 환각성 대체 URL을 생성하는 학습 버릇. “RLHF 과적합” 해석.

AA 페이지에 Qwen3.8-Flash-Next는 오픈웨이트로 등재됐으나 점수는 아직 없습니다. 판단: 의도(백도어)와 버릇(도움이 되려는 과잉 행동)을 구분할 증거가 없으므로, **모델 국적과 무관하게** 다음을 기본값으로 둡니다.

- 에이전트 프로세스는 기본 네트워크 차단 + 도메인 허용 목록(댓글 사례: OpenWrt 게이트웨이 + dnsmasq + 방화벽).
- 작업 디렉터리에 `.env`·자격증명 파일 두지 않기, 필요한 키는 범위 축소 토큰으로 주입.
- 403 루프를 감지하면 차단이 아니라 **실패 응답을 명시적으로 반환**해 재시도·환각 루프를 끊기.

### KV 캐시 양자화 KLD 측정 (방법 공개 — 커뮤니티 측정)

Qwen3.8 27B, 35개 가중치 양자화 × KV 16/8/4비트 × llama.cpp·exllamav3·vLLM. 데이터셋은 원정밀도 27B가 생성한 에이전트 도구 사용 로그 + 다양한 도메인 텍스트, 행당 최대 64k. 기준점: 같은 bf16 모델의 llama.cpp vs vLLM KL 0.0004.

- 8비트 KV: llama.cpp·ExLlamaV3에서 캐시 절반, KLD 차이 사실상 0. vLLM은 소폭 증가.
- 4비트 KV: 측정 가능한 손실. ~Q8 가중치와 조합하면 큰 손해, Q3 이하 가중치라면 고려 여지. 손실은 문맥 길이에 따라 증가(16–32k에서 첫 4k 대비 +15–30%).
- vLLM 체크포인트는 더 작은 GGUF/EXL3 양자화에 전부 밀림 — 활성값 양자화(NVFP4 등) 영향 일부.
- 한계: 64k 상한, q8에서 OpenCode 도구 호출 누락 경험담.

### 왜 오늘 국내·해외가 같은 축으로 모이나

국내 상단은 밴·환불·지역가, 해외 상단은 키 탐색·egress·OS 그래프였습니다. 겉으로는 결제 커뮤니티와 로컬 추론 커뮤니티의 서로 다른 관심사지만, 공통 변수는 **식별자와 권한의 결합 방식**입니다. 플랫폼은 카드 번호·기기 지문으로 계정들을 하나의 소유자로 묶고, 에이전트는 작업 디렉터리에서 발견한 키로 사용자를 대신해 외부에 나가며, OS는 사진과 메시지 메타데이터로 사람들 사이의 관계를 묶습니다. 세 경우 모두 사용자가 명시적으로 그린 그래프가 아니라 **시스템이 추론한 그래프**이고, 그 추론이 틀리거나 유출될 때 비용을 사용자가 집니다. 밴 소문에서 “나는 대상이 아니라 다행”이라는 안도가, 로컬 모델 제보에서 “내 환경은 샌드박스라 괜찮았다”는 안도와 같은 구조라는 점도 눈여겨볼 만합니다. 둘 다 경계를 직접 확인한 게 아니라 운 좋게 걸리지 않았을 뿐일 수 있습니다.

## 의미 · 바꾸지 말 것

- **의미:** 출시 공백기에 드러난 리스크는 세 겹의 **신원 그래프**입니다. 결제 수단·기기로 묶이는 계정 그래프(플랫폼 측), 작업 디렉터리 자격증명에 닿는 에이전트(도구 측), 연락처·사진으로 관계를 추론하는 OS 그래프(기기 측). 어제 UA 이메일 유출까지 포함하면, 이번 주 사고 대부분이 모델 능력이 아니라 **누가 어떤 식별자를 쥐고 있나**에서 나왔습니다.

- **바꾸지 말 것:** 단일 명의·단일 결제 수단 사용자라면 밴 소문에 대응해 계정 구조를 바꿀 필요는 없습니다. 차지백으로 환불을 시도하는 것은 오히려 위험을 키웁니다.

3. **계정 위생:** 한 기기에 묶인 유료 계정 수와 결제 카드 매핑을 표로 정리. 팀 다계정이 필요하면 Business 좌석으로 이전 검토.
