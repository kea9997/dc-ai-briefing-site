### 2) “How to be more ambitious” 번역 — 고도·깊이·범위 (원문 확인)

**고급 사용자 관점:** 결과 단위 위임은 곧 **장기 실행·자율 루프**를 뜻하고, 이는 오늘 해외 1번(영구 허용 규칙)과 정면으로 연결됩니다. 고도를 올릴수록 승인 마찰을 줄이고 싶어지고, 그 마찰 제거가 비밀을 디스크에 박제합니다. 야망과 권한 설계는 한 세트로 가야 합니다.

### 3) Argon의 “가짜 툴콜” (사용자 제보 — 미확인)

「아르곤이 문제인게」(조회 약 2,260·추천 25·댓글 25): 웹 검색 지시에 Argon이 **tool call을 발행하지 않고, 툴콜 중간 메시지 형태를 최종 응답 안에 모사한 뒤 “검색 결과 없음”**으로 답했다는 캡처. 재차 “검색 툴 써”라고 하자 그때 실제 호출. 댓글에 동일 경험(“나만 그런 게 아니었군”), “검색 존나 안 함”이 붙었습니다. 「제미나이 도망친 곳에 낙원은 없네」(환각 불만)도 같은 날.

**기술적 해석(미확인):** 대화 기록에 이전 툴 결과 블록이 텍스트로 남아 있거나, 앱 UI가 중간 상태 메시지를 응답 스트림과 섞어 보여 줄 때 모델이 **형식을 모방**하는 패턴으로 보입니다. 비용 절감용 라우팅(검색 생략 판단)일 가능성도 있지만 근거 없음. 대응: API·에이전트 환경이라면 응답 텍스트가 아니라 **실제 tool_use 이벤트/트레이스**로 검색 여부를 판정하고, 소비자 앱에선 인용 URL 필수 + 열람 검증을 프롬프트 규칙으로 고정하세요. 11-08 해외의 “Qwen Flash Next가 지어낸 URL로 fetch” 제보와 결이 같습니다 — 도구 경계에서의 환각은 벤더 불문입니다.

**의미:** 생성 비용이 0에 수렴하자 커뮤니티의 신호 필터가 **형식 탐지**로 이동했습니다. 결과물을 공유할 때 차별점(벤치·실사용 지표·재현 절차) 없이 “만들었다”만 있으면 자동으로 슬롭 분류됩니다. 4주년 대회가 “범용성·재현성·전달력”으로 평가하는 것도 같은 맥락입니다.

## 해외 — 교차 확인

### 1) `settings.local.json` 유출의 구조 (확인 — Apiiro / THN / LATENT / HN)

메커니즘: Claude Code가 Bash 명령 승인 시 “Yes, and don't ask again”을 고르면 프로젝트의 `.claude/settings.local.json`에 allow 규칙을 씁니다. 규칙은 프롬프트가 제시한 범위 — 패턴(`Bash(npm test:*)`)일 수도, **정확한 명령 문자열**일 수도 있고, 후자면 인라인 비밀번호·토큰이 평문으로 남습니다.

Apiiro 조사(11-01~03 수집): `settings.local.json` 104,185개(103,617 저장소)·공유 `settings.json` 76,011개, 이력 43,120 저장소. 비밀 판정은 공급자 키 포맷 매칭 또는 “공개 호스트와 같은 줄의 비포맷 비밀번호”, 이후 LLM 리뷰어 동의가 필요(2,774개 후보 중). 결과:

- 1,122 파일(1.08%)에 1,379 고유 비밀, 그중 36.3%가 DB 직결(DB 비밀번호 379), SSH 43, GitHub/GitLab/npm 토큰 42, AWS 키 23.
- 8KB 초과 파일은 전체의 2.6%인데 비밀 보유 파일의 24.3% — **승인이 누적될수록 위험 상승**.
- gitleaks 50.3%, TruffleHog 57.3% 탐지, 병용 시에도 215개(19.2%) 미탐 — 포맷 없는 인라인 비밀번호 탓.
- 과거 커밋에만 남은 비밀 734개. 보도에 함께 돈 2,539 수치는 다른 파일·이력을 합친 값이라 혼용 주의.
- Apiiro는 자격 증명의 유효성을 시험하지 않았고, 통보받은 한 회사가 키가 살아 있었다고 확인.

Claude Code 팀(Boris, HN): 파일은 로컬 전용이며 Claude가 생성 시 자동 gitignore — 이번 건은 수동 생성·강제 추가. 비밀 스크러빙은 그동안 하지 않았으나 검토 중. 반론: 자동 제외는 해당 머신의 `.git/info/exclude` 등록이라 **다른 머신·컨테이너·복사 폴더·이미 추적된 파일엔 무효**(LATENT). HN 상위 댓글은 “버튼이 노출하는 게 아니라 커밋이 노출” — 맞는 말이지만 에이전트가 `git add -A`류를 자율 수행하는 환경에선 그 경계가 흐려집니다.

**대응(우선순위):** ① `git log --all -- .claude/settings.local.json`로 이력 확인 → ② **비밀 회전 먼저** → ③ `git rm --cached` + 저장소 자체 `.gitignore`(전역 exclude는 클론을 안 따라감) → ④ 로컬 파일에서 비밀 포함 규칙 삭제 → ⑤ 비밀은 `$DB_URL` 같은 환경 변수·시크릿 매니저 참조로, 승인은 패턴 단위로 → ⑥ 해당 경로 전용 커스텀 스캐너 규칙 추가. 11-07의 UA 이메일 유출과 합치면 이번 주 Claude Code 이슈는 **모델이 아니라 하네스의 상태 저장**에서 나왔습니다.
